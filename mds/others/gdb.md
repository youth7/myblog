# 一个典型的使用GDB的过程

### 1️⃣ 查看有哪些函数（全局符号）

使用 `info functions` 命令。它会列出整个程序（包括标准库）中所有已定义的函数名称。

**操作：**
```gdb
(gdb) info functions
```
**如果你想只看特定文件（例如只关心 `b.c`）或特定前缀（如 `test`）中的函数**，可以加上正则表达式：
```gdb
(gdb) info functions ^test  # 查看所有以 test 开头的函数
(gdb) info functions b.c    # 查看 b.c 文件中定义的函数（GDB 会列出包含该文件名的符号）
```

---

### 2️⃣ 在特定函数（`test`）上打断点
使用 `break`（简写为 `b`）命令，直接加上函数名。

**操作：**
```gdb
(gdb) break test
```
**特殊情况处理：**
如果 `a.c`、`b.c`、`c.c` 里有 **同名的静态函数（static）**，或者存在同名函数重载（C++），GDB 会提示歧义。此时你需要指定具体文件：
```gdb
(gdb) break b.c:test   # 仅在 b.c 文件中的 test 函数打断点
```

---

### 3️⃣ 让程序运行到 `test` 函数
如果你刚启动 GDB，直接输入 `run`（简写为 `r`）。

**操作：**
```gdb
(gdb) run
```
因为你在第 2 步已经打了断点，程序会在执行到 `test` 函数的**入口处**（即函数体的第一行有效代码）自动暂停，无需额外操作。

**补充**：如果程序已经在运行中（例如你正在调试循环），想跳到 `test` 函数处，可以使用 `continue` 让它继续跑，直到命中 `test` 的断点。

---

### 4️⃣ 查看 `test` 函数的源代码
当程序在 `test` 函数处暂停时，使用 `list`（简写为 `l`）命令。

**操作（此时光标已在断点处）：**
```gdb
(gdb) list
```
这通常会显示断点周围的 10 行代码。

**如果你想看 `test` 函数的完整代码（从头到尾）**，可以直接指定函数名：
```gdb
(gdb) list test
```
如果函数较长，按回车键（重复上一次命令）会继续向下翻页。
